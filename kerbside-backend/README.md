# Kerbside Pages data and live Worker

Kerbside 0.6 separates static timetable delivery from live bus positions:

- **Cloudflare Pages** serves official stop, timetable and journey-pattern JSON.
- **Cloudflare Worker** protects the BODS key and proxies live vehicle positions only.
- **GitHub Actions** rebuilds England's regional BODS timetable data and deploys it to Pages.

No R2 bucket, R2 API token or R2 billing setup is required.

## Public endpoints

Static data is deployed to `https://kerbside-data-zetabun.pages.dev`:

- `GET /manifest.json` - national build status and regional bounds.
- `GET /regions/{region}/tiles/{tile}.json` - nearby official stop metadata for one geographic tile.
- `GET /regions/{region}/departures/{prefix}.json` - a balanced timetable shard selected by the stop's hash.
- `GET /regions/{region}/patterns/{prefix}.json` - ordered journey patterns loaded only when needed.

`bus.html` uses that Pages hostname directly, so timetable traffic does not consume Worker requests.

Kerbside 0.6.39 hardens service-calendar and overnight departure handling. Kerbside 0.6.40 generates timetable rows by their displayed target date rather than by a fixed set of nearby origin service dates. ## One-time Cloudflare setup

1. Create a Cloudflare API token with:
   - **Account / Cloudflare Pages / Edit**
   - **Account / Workers Scripts / Edit**
2. Add these GitHub Actions repository secrets:
   - `BODS_KEY`
   - `CLOUDFLARE_ACCOUNT_ID`
   - `CLOUDFLARE_API_TOKEN`
3. Run **Build Kerbside national timetable data** manually.
   - The workflow creates the `kerbside-data-zetabun` Pages project when it does not exist.
   - It builds all nine English BODS regions and deploys the static site.
4. Run **Deploy Kerbside Worker** manually.
5. Confirm:
   - `https://kerbside-data-zetabun.pages.dev/manifest.json` returns a national manifest.
   - the Worker's `/health` response says `role: "live-only"` and `bods: true`.
6. Add the repository Actions variable `KERBSIDE_NATIONAL_ENABLED=true` to enable automatic daily timetable deployments. Worker deployments run independently whenever Worker source, package or Wrangler configuration changes.

Do not put BODS or Cloudflare credentials in `bus.html`, source code or repository variables.

## Pages free-tier safeguards

The builder writes lightweight 0.05-degree stop-index tiles plus balanced two-character departure and pattern shards. This prevents dense city timetables from producing oversized geographic files. The workflow fails before deployment when:

- the site contains more than 20,000 files; or
- any individual asset reaches 25 MiB.

A `_headers` file enables cross-origin browser access and sets CDN caching for manifests, tiles and pattern shards.

Exact ordered-route evidence now overrides contradictory town-anchor GPS movement without weakening explicit timetable direction filters, and Both mode no longer discards a valid journey merely because route and town-centre direction labels disagree. Kerbside 0.6.61 corrects live vehicle identity and route evidence. A live record is now keyed by journey **and** vehicle reference together: where an operator publishes one journey or block code for several buses working it, every bus is kept instead of all but the last being silently discarded, and the survivor no longer looked like a single vehicle teleporting between them — which reset its track each poll and left it with no movement direction, no learned speed and a degraded ETA. A bus that starts its next journey now retires the record it was reporting under a moment earlier, and a straggling report for a finished journey no longer resurrects that identity beside the newer one, so the same vehicle can no longer appear twice on the board as a second frozen departure. `knownRoutes()` no longer writes OpenStreetMap-mapped and locally observed lines into the cached timetable route set, which had promoted those routes to "timetable verified" route evidence until the cache expired. Leave alerts re-arm on an empty board, a saved stop is restored by string-normalised id on both stop-discovery paths, and journey geometry is resolved once per vehicle per pass rather than projecting every bus onto its full route pattern up to four times.

Kerbside 0.6.62 makes the live vehicle marker move continuously between operator reports and corrects the journey stop list. The glide is now sized from each vehicle's own measured reporting cadence rather than a fixed slice of it: on a thirty-second feed the marker previously covered 180 m, stalled for twelve seconds and then leapt the remaining 120 m the instant the next fix arrived, and once a vehicle passed the staleness threshold it was thrown backwards by the entire distance it had just been shown covering. The lead now spans the expected gap with a margin, holds its last estimate at the ceiling instead of reverting, and the marker transition is derived from the motion tick so one step is still easing when the next replaces it. Estimated arrival times, stop matching and at-stop claims continue to use confirmed GPS records only. In the ordered stop list, the stop a bus is standing at is no longer greyed out as a previous stop: stops behind the bus read as dulled grey, the stop it is at or heading for reads green, and the user's own stop stays amber and full contrast so it remains findable in a long list.

Kerbside 0.6.63 removes the first-load freeze on desktop. Every bus within the 9 km area was given its own Leaflet marker, each promoted to a compositor layer by the glide and repositioned once a second; when a whole city's feed arrived at once this stalled the browser. Measured on desktop before the change: 150 markers held a steady 4 ms frame, 400 produced a ~1 s stall, and 700 rendered three frames in 2.2 seconds. Vehicle markers are now capped at the nearest 120, never dropping a bus that is listed on the board or currently selected, which holds a steady 4 ms frame with a thousand buses in the feed. The vehicles themselves are unchanged: route matching, direction, estimates and the live diagnostics still run over every vehicle received, and the departure board is unaffected. Kerbside 0.6.64 fixes two departure-board presentation faults. The dot-matrix texture was an absolutely positioned overlay inset into the scrolling list, which covers only the visible screenful and then scrolls away with the content: on a long board it stopped partway down, measured as a 467px overlay over 2062px of content. It is now painted as the scroll container's own tiled background so it covers the whole scrollable height. The board is also rebuilt wholesale on every refresh and on each five-second tick, which returned anyone reading a long list, or scrolling an expanded journey's stop list, to the top each time. Both scroll positions are now carried across the rebuild, while selecting a different vehicle correctly starts that journey's stop list at the top.

Kerbside 0.6.65 makes the between-report glide follow the journey's own geometry even when no authoritative road shape exists. Only about 60% of national patterns carry a GTFS shape and in London almost none do, so for the remainder the builder stores the ordered stop positions as the pattern's points. Route distance, remaining metres and journey progress already measure along that corridor, but the visual glide refused it and fell back to projecting the last bearing in a straight line, which carries on through every bend. The glide now follows the stop corridor, requiring the vehicle to be within 200 m of it rather than the 500 m allowed for a true shape, because a chord between stops is only a good approximation of the road where the vehicle is actually near it. Measured on a 1500 m-radius bend twenty seconds after the last report: 53 m average error before, 7 m after, against 5 m for a genuine GTFS shape. The drawn route line remains gated on an authoritative shape — this guides motion and never draws a road Kerbside cannot verify — and the journey panel now states plainly that the operator publishes no road shape rather than implying a rebuild is pending.

Kerbside 0.6.66 stops the hold-open resurrecting a bus that has turned away. The hold exists for momentary weakness in the evidence — a bearing wobble at a junction, a pattern shard still loading — but it also applied when consecutive GPS fixes showed the vehicle measurably retreating from the stop, so a bus moving away was kept on the board on its previous countdown. Direction and heading-away rejections are now hard drops when the measured movement trend retreats; bearing alone remains holdable, and every other holdable reason is unchanged. This restores the repository's own long-standing production assertion that a receding vehicle is rejected.

Kerbside 0.6.67 corrects the journey retirement introduced in 0.6.61. Retiring a superseded journey depends on knowing two records are the same physical bus, and a vehicle reference alone does not establish that: some operators publish a single placeholder or fleet code for every bus working a route, so five simultaneous buses collapsed to one. A snapshot settles it — one bus cannot report two journeys at once, so a code appearing more than once in the same batch carries no identity and never retires a sibling, and a record that reported in the current batch is plainly still running whatever else shares its code. Buses sharing a journey code remain separate, a bus starting its next journey still retires the record it was reporting under, and a straggling report is still skipped.

Kerbside 0.6.68 preserves simultaneous buses even when an operator reuses both journey and vehicle references. Stable SIRI activity identifiers now separate colliding records, shared fleet placeholders remain shared across partial polls, and timetable corridor matching can recover from private journey aliases using ordered route movement and schedule timing. The larger busy-stop scan budget and dedicated five-bus regression apply to every route.

Kerbside 0.6.69 closes the remaining cross-poll multi-bus identity gap. Corridor XML responses are parsed as one identity batch while retaining their source-plan indexes, activity identities persist across nearby and corridor polls, existing unsplit records are promoted when a later collision is discovered, and identifier-free activities use bounded nearest-track slots instead of silently overwriting one another. Exact duplicate observations across overlapping boxes are still deduplicated. SIRI ValidUntilTime is now respected as a hard producer expiry, and dedicated regressions cover combined boxes, separate polls, anonymous activities, overlapping responses and expired reports.

Kerbside 0.6.70 adds roadworks and disruption warnings to the departure board. A scheduled GitHub Action republishes the Department for Transport SIRI-SX disruptions archive as a compact `disruptions.json` beside `bus.html`, which makes it same-origin and keeps the browser off a 5.8 MB national XML that carries no CORS header. Matching is by exact ATCO stop code against the ordered stops of the journey patterns already loaded for the selected stop, so each warning states whether the works fall before the stop, at it, or a counted number of stops further along, and which routes they affect. Line names are deliberately never matched: most published names are shared by several operators nationally. Lapsed entries are filtered on their SIRI validity window rather than trusting the published progress value, because a large share of the archive has already expired. Coverage depends on what each local transport authority publishes, so the panel stays hidden where nothing is reported.
