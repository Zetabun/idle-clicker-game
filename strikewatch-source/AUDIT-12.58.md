# Strikewatch Build 12.58 Audit

**Release:** Strikewatch Build 12.58 — Desktop Command Centre  
**Build ID:** `12.58.0-desktop-command-centre`  
**Save schema:** 19, unchanged  
**Diagnostics schema:** 1, unchanged

## Scope and source authority

The complete uploaded Build 12.57 source archive was used as the authority for this release. All **58 incoming Markdown files** were enumerated and read before implementation. This audit brings the package to **59 Markdown files**.

Build 12.58 is a desktop-only Command HQ presentation and usability pass. It keeps the established phone and mobile-landscape interface as the visual authority below `1024px`, while turning Command HQ at `1024px` and wider into a supported PC workspace rather than an enlarged phone layout.

The modular source remains authoritative. `js/strikewatch.dev.js` and `dist/strikewatch-build-12.58.html` are generated by `build.py` and were not edited directly.

## Design boundary

The implementation deliberately separates the two presentation targets:

- below `1024px`, the existing portrait and mobile-landscape cascade, route overflow arrows, touch targets, safe-area handling and live-match dock remain unchanged;
- at `1024px` and wider, a final guarded desktop layer in `css/game.css` owns the PC shell, navigation density, content width, layout grids and readability adjustments.

The complete Build 12.57 stylesheet—**779,869 bytes**—remains a byte-identical prefix of the Build 12.58 stylesheet. The new desktop work is appended after it and adds **33,356 bytes**. No existing mobile CSS rule was rewritten.

## Desktop Command Centre implementation

### 80-pixel command bar

The desktop top bar is now a stable 80-pixel command surface with:

- readable account, department and manager context;
- labelled **Inbox**, **Calendar** and **Match** shortcuts instead of icon-only controls;
- retained notification badges and existing route actions;
- clearer hover and keyboard-focus treatment;
- a bounded End Day control rather than a stretched mobile-style action.

The shortcut labels exist in shared markup but are hidden below `1024px`.

### Department rail and live section identity

The left navigation rail now uses supported desktop widths:

- `252px` at 1024–1279px;
- `292px` at ordinary desktop widths;
- `304px` at 1440px and wider.

The rail presents one desktop-only department identity block. `menuSections` in `js/50-ui-menus.js` now supplies a section-specific kicker and title for Operations, Team, Armoury, Supplies and Club, and the existing `updateMenuUI()` route authority updates the block. The original mobile command mark and its copy remain separate and unchanged.

Primary navigation entries use more informative descriptions, larger type, clearer active/hover states and stable access badges without changing section or route ownership.

### Desktop route navigation

The secondary route bar is no longer a phone-style horizontal scroller on PC. At desktop widths it becomes a width-aware grid that:

- fits or wraps available routes;
- removes horizontal arrow controls;
- gives every route a readable label and supporting status line;
- expands to its real multi-row height at 1024px rather than overlapping the first content panel;
- remains sticky inside the management workspace.

### Bounded workspaces and section layouts

Command HQ content is centred with responsive gutters and a maximum desktop canvas of `1520px`, expanding to `1600px` at very wide screens. Long copy no longer stretches edge-to-edge.

Existing modules receive desktop-specific presentation without changing their data or actions, including:

- wider Command Centre planning and status panels;
- two-, three-, four- and five-column squad/card grids according to available width;
- denser recruitment and transfer rows with controlled column reduction at 1024px;
- a two-pane Inbox list and reader where space permits;
- larger finance, calendar, Armoury and Supply Depot surfaces;
- stable focus outlines and desktop control heights;
- a final PC-only readability floor for legacy management labels that previously rendered at 5.5–7px.

The final 1024px and 1366px route audits found no visible `#menuContent` text below 8px and no interactive control shorter than 36px.

## Shared markup and JavaScript changes

`index.html` adds only presentation hooks:

- desktop-only shortcut labels;
- a retained mobile command mark;
- a separate desktop command mark with section identity IDs;
- Build 12.58 title, asset query and build stamp.

`js/00-core.js` updates the build metadata and caches the three desktop identity elements.

`js/50-ui-menus.js` adds department presentation copy and updates the new elements from the already-authoritative active section. No second navigation system, state model or persistence field was introduced.

## Preserved mobile interface

A direct Build 12.57 versus Build 12.58 comparison was run at:

- 320 × 720 portrait;
- 375 × 812 portrait;
- 390 × 844 portrait;
- 402 × 874 portrait;
- 430 × 932 portrait;
- 844 × 390 mobile landscape.

All shared shell geometry, computed layout styles, route state and overflow values were identical at every viewport, and both builds were free of captured runtime errors.

Pixel comparison was also performed at 320 × 720 and 844 × 390 after disabling animation. The only differences were raster-level noise:

- 320 × 720: 1 changed pixel, maximum channel delta 1;
- 844 × 390: 3 changed pixels, maximum channel delta 1.

The general-purpose comparator reports a structural mismatch because Build 12.58 contains a hidden desktop shortcut-label node that does not exist in Build 12.57; all shared geometry and styles match. The desktop section identity remains `display: none` below `1024px`, and the original mobile identity is the only visible mark in mobile landscape.

## Second-pass defects caught and corrected

The independent verification pass found and fixed issues that were not safe to leave for release:

1. The first dynamic section-identity implementation reused the shared mobile mark and changed the 844 × 390 sidebar height. The original mobile block was restored byte-for-byte and the dynamic identity moved into a desktop-only sibling.
2. Both identity blocks were initially visible on desktop after that split. The final breakpoint selector now displays exactly one desktop mark and hides the mobile mark at `1024px` and wider.
3. Multi-row route navigation at 1024px initially retained a fixed-height shell and could overlap the first content panel. The desktop shell now owns its measured grid height.
4. Legacy management modules still carried 5.5–7px labels into PC layouts. A targeted desktop-only typography floor raised status, lock, market, tactics, profile, Armoury and Command Index microcopy without touching mobile or 3D geometry.
